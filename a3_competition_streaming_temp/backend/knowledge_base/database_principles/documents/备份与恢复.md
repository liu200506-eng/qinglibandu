# 备份与恢复

## 一、备份的重要性

数据库备份是数据安全的最后一道防线，用于：
- 防止数据丢失
- 灾难恢复
- 数据迁移
- 测试和开发

## 二、备份类型

### 按备份范围分类

1. **全量备份**
   - 备份整个数据库
   - 恢复简单，速度慢
   - 占用空间大

2. **增量备份**
   - 备份自上次备份以来变化的数据
   - 备份速度快，占用空间小
   - 恢复需要全量备份+所有增量备份

3. **差异备份**
   - 备份自上次全量备份以来变化的数据
   - 介于全量和增量之间
   - 恢复需要全量备份+最后一次差异备份

### 按备份状态分类

1. **冷备份**
   - 数据库关闭时进行备份
   - 数据一致性好
   - 业务中断

2. **热备份**
   - 数据库运行时进行备份
   - 不影响业务
   - 需要支持备份的DBMS

## 三、恢复策略

### 恢复类型

1. **完全恢复**
   - 恢复到故障发生前的状态
   - 需要完整的备份和日志

2. **不完全恢复**
   - 恢复到指定时间点
   - 用于误操作恢复

### 恢复步骤

1. 确定恢复目标
2. 准备备份文件
3. 执行恢复操作
4. 验证恢复结果

## 四、日志的作用

### 日志类型

1. **重做日志（Redo Log）**
   - 记录数据的修改操作
   - 用于前滚恢复
   - 确保事务的持久性

2. **回滚日志（Undo Log）**
   - 记录数据修改前的值
   - 用于回滚操作
   - 确保事务的原子性

### WAL（Write-Ahead Logging）

- 修改数据前先写日志
- 确保日志写入后再修改数据
- 提高恢复的可靠性

## 五、备份策略建议

- 定期全量备份（如每周）
- 每日增量或差异备份
- 定期测试恢复过程
- 备份文件异地存储
- 使用自动化备份工具
