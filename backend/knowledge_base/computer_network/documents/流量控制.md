# TCP流量控制

## 流量控制概述

流量控制是TCP的重要功能，用于防止发送方过快地发送数据，导致接收方缓冲区溢出。

### 流量控制的目的

1. **防止接收方缓冲区溢出**
2. **根据接收方的处理能力调整发送速率**
3. **保证数据的可靠传输**

## 滑动窗口机制

### 滑动窗口概述

TCP使用滑动窗口机制实现流量控制，接收方通过通告窗口（rwnd）告诉发送方自己的缓冲区可用空间。

### 窗口大小

窗口大小表示发送方可以连续发送的字节数，无需等待确认。

- **发送窗口**：由发送方维护，取决于接收方的通告窗口
- **接收窗口**：由接收方维护，取决于缓冲区可用空间

### 窗口滑动

1. 发送方发送数据
2. 接收方确认数据，并更新通告窗口
3. 发送方根据新的通告窗口调整发送窗口
4. 发送方继续发送数据

## 流量控制过程

### 初始阶段

1. 建立连接时，双方交换初始窗口大小
2. 发送方根据接收方的通告窗口发送数据

### 数据传输阶段

1. 接收方接收数据后，计算剩余缓冲区空间
2. 接收方在ACK报文中携带新的通告窗口
3. 发送方根据通告窗口调整发送速率

### 缓冲区满的情况

1. 如果接收方缓冲区已满，通告窗口为0
2. 发送方停止发送数据
3. 接收方处理完数据后，发送非零的通告窗口

## 流量控制与拥塞控制的区别

| 特性 | 流量控制 | 拥塞控制 |
|------|---------|---------|
| 目的 | 防止接收方缓冲区溢出 | 防止网络拥塞 |
| 控制对象 | 发送方与接收方之间 | 整个网络 |
| 机制 | 滑动窗口（rwnd） | 拥塞窗口（cwnd） |
| 实现位置 | 端到端 | 发送方 |

## 流量控制示例

假设接收方缓冲区大小为1000字节：

1. 初始通告窗口：1000字节
2. 发送方发送500字节数据
3. 接收方确认数据，通告窗口：500字节
4. 发送方再发送500字节数据
5. 接收方确认数据，通告窗口：0字节
6. 发送方停止发送
7. 接收方处理完数据，通告窗口：1000字节
8. 发送方继续发送

## 总结

流量控制通过滑动窗口机制，根据接收方的处理能力动态调整发送速率，确保数据的可靠传输。
