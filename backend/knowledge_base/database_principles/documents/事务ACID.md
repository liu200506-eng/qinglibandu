# 事务ACID

## 概述

事务是数据库管理系统中的基本概念，是一组不可分割的操作序列。事务必须满足ACID特性，即原子性、一致性、隔离性和持久性。

### 事务的定义

事务是一个或多个数据库操作的集合，这些操作要么全部执行成功，要么全部不执行。

### 事务的状态

**活动状态**：事务正在执行
**部分提交状态**：事务的最后一个操作已经执行，但结果尚未写入磁盘
**失败状态**：事务执行过程中发生错误
**中止状态**：事务已回滚，数据库恢复到事务开始前的状态
**提交状态**：事务已成功提交，结果已写入磁盘

## 原子性（Atomicity）

### 定义

原子性是指事务中的所有操作要么全部执行成功，要么全部不执行。如果事务中的任何一个操作失败，整个事务都应该回滚到事务开始前的状态。

### 示例

```sql
-- 转账事务
BEGIN TRANSACTION;

-- 从A账户扣除100元
UPDATE accounts SET balance = balance - 100 WHERE account_id = 'A';

-- 向B账户增加100元
UPDATE accounts SET balance = balance + 100 WHERE account_id = 'B';

-- 如果两个操作都成功，则提交事务
COMMIT;

-- 如果任何一个操作失败，则回滚事务
ROLLBACK;
```

### 实现机制

**日志**：
- 记录事务的每一个操作
- 用于回滚和恢复

**锁**：
- 防止其他事务干扰

**两阶段提交**：
- 用于分布式事务

## 一致性（Consistency）

### 定义

一致性是指事务执行前后，数据库的完整性约束没有被破坏。

### 示例

```sql
-- 转账事务保持一致性
-- 转账前：A账户余额 + B账户余额 = 总余额
-- 转账后：A账户余额 + B账户余额 = 总余额（不变）
```

### 完整性约束

**实体完整性**：
- 主码不能为空

**参照完整性**：
- 外码必须引用存在的主码

**用户定义完整性**：
- 用户自定义的约束条件

## 隔离性（Isolation）

### 定义

隔离性是指多个事务并发执行时，一个事务的执行不能被其他事务干扰。

### 并发问题

**脏读**：
- 一个事务读取了另一个事务未提交的数据

**不可重复读**：
- 一个事务在执行过程中，多次读取同一数据，结果不一致

**幻读**：
- 一个事务在执行过程中，两次查询的结果集大小不同

### 示例

**脏读**：
```sql
-- 事务1
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE account_id = 'A';
-- 事务1未提交

-- 事务2
BEGIN TRANSACTION;
SELECT balance FROM accounts WHERE account_id = 'A';
-- 读取到事务1未提交的数据（脏数据）
```

**不可重复读**：
```sql
-- 事务1
BEGIN TRANSACTION;
SELECT balance FROM accounts WHERE account_id = 'A'; -- 1000元
-- 事务2修改了A账户的余额
SELECT balance FROM accounts WHERE account_id = 'A'; -- 900元（不可重复读）
```

**幻读**：
```sql
-- 事务1
BEGIN TRANSACTION;
SELECT COUNT(*) FROM accounts; -- 100个账户
-- 事务2插入了新账户
SELECT COUNT(*) FROM accounts; -- 101个账户（幻读）
```

### 隔离级别

**读未提交（READ UNCOMMITTED）**：
- 允许读取未提交的数据
- 最低隔离级别

**读已提交（READ COMMITTED）**：
- 只允许读取已提交的数据
- 防止脏读

**可重复读（REPEATABLE READ）**：
- 在事务执行期间，多次读取同一数据的结果一致
- 防止脏读和不可重复读

**串行化（SERIALIZABLE）**：
- 事务串行执行
- 最高隔离级别，防止所有并发问题

### 隔离级别对比

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|-----------|------|
| 读未提交 | 允许 | 允许 | 允许 |
| 读已提交 | 防止 | 允许 | 允许 |
| 可重复读 | 防止 | 防止 | 允许 |
| 串行化 | 防止 | 防止 | 防止 |

## 持久性（Durability）

### 定义

持久性是指事务提交后，其结果应该永久保存到数据库中，即使系统崩溃也不会丢失。

### 实现机制

**日志**：
- 记录事务的每一个操作
- 系统崩溃后，通过日志恢复数据

**检查点**：
- 定期将内存中的数据写入磁盘
- 减少恢复时间

**备份**：
- 定期备份数据库
- 用于灾难恢复

## 事务的实现

### 日志

**分类**：

**重做日志（Redo Log）**：
- 记录事务对数据库的修改
- 用于在系统崩溃后重做已提交的事务

**撤销日志（Undo Log）**：
- 记录事务的反向操作
- 用于回滚未提交的事务

### 两阶段提交（2PC）

**阶段1：准备阶段**
- 协调者向所有参与者发送准备请求
- 参与者执行事务，但不提交
- 参与者向协调者发送准备就绪或失败消息

**阶段2：提交阶段**
- 如果所有参与者都准备就绪，协调者发送提交请求
- 参与者提交事务
- 如果任何参与者失败，协调者发送回滚请求

### 三阶段提交（3PC）

**改进**：
- 在2PC的基础上增加了预提交阶段
- 减少了阻塞时间

## 总结

ACID是事务的四个基本特性：
- **原子性**：要么全部执行，要么全部不执行
- **一致性**：事务前后数据保持一致
- **隔离性**：事务之间相互隔离
- **持久性**：事务提交后永久保存

理解ACID特性对于设计可靠的数据库系统至关重要。
