# 规范化

## 概述

规范化是数据库设计的重要步骤，通过消除数据冗余和异常，提高数据的一致性和完整性。

### 规范化的目标

1. **消除数据冗余**：避免重复存储相同的数据
2. **消除更新异常**：避免更新数据时出现不一致
3. **消除插入异常**：避免无法插入某些数据
4. **消除删除异常**：避免删除数据时丢失其他数据

## 函数依赖

### 定义

函数依赖是关系模式中属性之间的一种约束关系。如果属性集X的值决定属性集Y的值，则称Y函数依赖于X，记为X → Y。

### 示例

```
关系模式：student(student_id, student_name, department, department_head)

函数依赖：
student_id → student_name
student_id → department
department → department_head
student_id → department_head (传递依赖)
```

### 分类

**完全函数依赖**：
- 如果X → Y，且对于X的任何真子集X'，都有X' ↛ Y，则称Y完全函数依赖于X。

**部分函数依赖**：
- 如果X → Y，且存在X的真子集X'，使得X' → Y，则称Y部分函数依赖于X。

**传递函数依赖**：
- 如果X → Y，Y → Z，且Y ↛ X，则称Z传递函数依赖于X。

## 范式

### 第一范式（1NF）

**定义**：关系模式中的每个属性都是不可再分的原子值。

**示例**：

```
不符合1NF：
┌────────────┬────────────┐
│ student_id │ courses    │
├────────────┼────────────┤
│ 1001       │ 数学,英语  │
└────────────┴────────────┘

符合1NF：
┌────────────┬─────────┐
│ student_id │ course  │
├────────────┼─────────┤
│ 1001       │ 数学    │
│ 1001       │ 英语    │
└────────────┴─────────┘
```

### 第二范式（2NF）

**定义**：在1NF的基础上，消除非主属性对码的部分函数依赖。

**示例**：

```
不符合2NF：
关系模式：enrollment(student_id, course_id, student_name, course_name)

函数依赖：
(student_id, course_id) → student_name (部分依赖：student_id → student_name)
(student_id, course_id) → course_name (部分依赖：course_id → course_name)

分解为2NF：
students(student_id, student_name)
courses(course_id, course_name)
enrollment(student_id, course_id)
```

### 第三范式（3NF）

**定义**：在2NF的基础上，消除非主属性对码的传递函数依赖。

**示例**：

```
不符合3NF：
关系模式：student(student_id, student_name, department, department_head)

函数依赖：
student_id → department
department → department_head
student_id → department_head (传递依赖)

分解为3NF：
students(student_id, student_name, department)
departments(department, department_head)
```

### BC范式（BCNF）

**定义**：在3NF的基础上，消除任何属性对码的部分函数依赖和传递函数依赖，即每个函数依赖的左部都包含码。

**示例**：

```
不符合BCNF：
关系模式：teacher(course_id, teacher_id, teacher_name)

函数依赖：
course_id → teacher_id
teacher_id → teacher_name
teacher_id → course_id

码：(course_id), (teacher_id)

分解为BCNF：
course_teacher(course_id, teacher_id)
teachers(teacher_id, teacher_name)
```

### 第四范式（4NF）

**定义**：在BCNF的基础上，消除非平凡的多值依赖。

**示例**：

```
不符合4NF：
关系模式：student(student_id, phone, course)

多值依赖：
student_id →→ phone
student_id →→ course

分解为4NF：
student_phone(student_id, phone)
student_course(student_id, course)
```

## 规范化步骤

### 需求分析

1. 确定实体和属性
2. 确定实体之间的关系

### 概念设计

1. 绘制ER图
2. 确定主码和外码

### 逻辑设计

1. 将ER图转换为关系模式
2. 检查函数依赖
3. 逐步规范化到更高范式

### 物理设计

1. 选择存储结构
2. 创建索引
3. 优化查询性能

## 规范化与反规范化

### 规范化的优点

1. **数据一致性**：避免数据冗余，保证数据一致
2. **数据完整性**：易于实现完整性约束
3. **可维护性**：修改数据只需修改一处

### 规范化的缺点

1. **查询性能**：多表连接可能降低查询效率
2. **设计复杂度**：需要更多的表和关系
3. **更新开销**：更新可能需要修改多个表

### 反规范化

**定义**：为了提高查询性能，有意引入数据冗余。

**方法**：
1. **合并表**：将多个表合并为一个表
2. **增加冗余列**：在表中增加冗余列
3. **创建汇总表**：预先计算并存储汇总数据

**适用场景**：
- 查询性能要求高
- 更新频率低
- 数据一致性要求不高

## 函数依赖的推理规则

### Armstrong公理

**自反律**：
- 如果Y ⊆ X，则X → Y

**增广律**：
- 如果X → Y，则XZ → YZ

**传递律**：
- 如果X → Y且Y → Z，则X → Z

### 导出规则

**合并规则**：
- 如果X → Y且X → Z，则X → YZ

**分解规则**：
- 如果X → YZ，则X → Y且X → Z

**伪传递规则**：
- 如果X → Y且WY → Z，则WX → Z

## 总结

规范化是数据库设计的核心：
- 1NF：原子性
- 2NF：消除部分依赖
- 3NF：消除传递依赖
- BCNF：消除所有非平凡依赖
- 4NF：消除多值依赖

根据实际需求选择合适的范式，平衡数据一致性和查询性能。
