# 并发控制

## 概述

并发控制是数据库管理系统中处理多个事务并发执行的技术，确保事务的ACID特性不被破坏。

### 并发控制的目标

1. **保证数据一致性**：并发事务执行的结果与串行执行的结果一致
2. **提高系统吞吐量**：允许多个事务同时执行
3. **减少等待时间**：合理分配资源，减少事务等待

## 封锁协议

### 封锁的概念

封锁是并发控制的基本方法，通过限制事务对数据的访问来防止并发问题。

### 封锁类型

**共享锁（S锁）**：
- 允许其他事务读取数据
- 不允许其他事务修改数据

**排他锁（X锁）**：
- 不允许其他事务读取或修改数据

### 封锁协议

**一级封锁协议**：
- 事务在修改数据前必须获得X锁
- 事务结束后释放X锁
- 防止丢失修改

**二级封锁协议**：
- 在一级封锁协议的基础上，事务在读取数据前必须获得S锁
- 读取完成后立即释放S锁
- 防止丢失修改和脏读

**三级封锁协议**：
- 在一级封锁协议的基础上，事务在读取数据前必须获得S锁
- 事务结束后释放S锁
- 防止丢失修改、脏读和不可重复读

### 两段锁协议

**定义**：事务分为两个阶段：
1. **扩展阶段**：事务只能获取锁，不能释放锁
2. **收缩阶段**：事务只能释放锁，不能获取锁

**示例**：

```sql
-- 扩展阶段
LOCK TABLE accounts IN SHARE MODE;
LOCK TABLE transactions IN EXCLUSIVE MODE;

-- 操作数据
SELECT balance FROM accounts WHERE account_id = 'A';
INSERT INTO transactions VALUES (...);

-- 收缩阶段
UNLOCK TABLE accounts;
UNLOCK TABLE transactions;
```

**特点**：
- 保证事务的可串行化
- 可能导致死锁

## 死锁

### 定义

死锁是指两个或多个事务互相等待对方释放锁，导致所有事务都无法继续执行。

### 示例

```sql
-- 事务1
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE account_id = 'A';
-- 需要等待事务2释放B账户的锁
UPDATE accounts SET balance = balance + 100 WHERE account_id = 'B';

-- 事务2
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE account_id = 'B';
-- 需要等待事务1释放A账户的锁
UPDATE accounts SET balance = balance + 100 WHERE account_id = 'A';
```

### 死锁的必要条件

1. **互斥条件**：资源只能被一个事务占用
2. **请求与保持条件**：事务持有资源的同时请求其他资源
3. **不剥夺条件**：资源不能被强制剥夺
4. **循环等待条件**：事务之间形成循环等待链

### 死锁的处理

**预防死锁**：
- 破坏死锁的必要条件
- 按顺序获取锁

**避免死锁**：
- 检测事务是否可能导致死锁
- 使用银行家算法

**检测死锁**：
- 定期检测系统中是否存在死锁
- 使用等待图

**解除死锁**：
- 选择一个事务作为牺牲品
- 回滚该事务，释放资源

## 可串行化调度

### 定义

可串行化调度是指并发执行的事务的结果与串行执行的结果一致。

### 冲突可串行化

**定义**：如果一个调度可以通过交换非冲突操作转换为串行调度，则该调度是冲突可串行化的。

**冲突操作**：
- 两个操作涉及同一数据
- 至少有一个操作是写操作

### 视图可串行化

**定义**：如果一个调度与串行调度在视图上等价，则该调度是视图可串行化的。

**视图等价**：
- 初始读相同
- 写读依赖相同
- 最终写相同

### 测试方法

**优先图法**：
- 构建事务之间的优先关系图
- 如果图中存在环，则调度不是冲突可串行化的

## 并发控制的实现

### 锁管理器

**功能**：
- 管理锁的申请和释放
- 检测锁冲突
- 维护锁表

**锁表结构**：
```
┌─────────┬───────┬──────┬─────────────┐
│ 数据项   │ 锁类型 │ 事务 │ 等待事务    │
├─────────┼───────┼──────┼─────────────┤
│ account │ S     │ T1   │ T2, T3      │
│ account │ X     │ T2   │ -           │
└─────────┴───────┴──────┴─────────────┘
```

### 时间戳

**定义**：
- 为每个事务分配一个唯一的时间戳
- 时间戳表示事务开始的顺序

**时间戳排序协议**：
- 如果事务T1的时间戳小于事务T2的时间戳，则T1先执行
- 如果冲突，回滚时间戳较大的事务

**多版本并发控制**：
- 为每个数据项维护多个版本
- 事务读取适合的版本
- 写操作创建新版本

### 乐观并发控制

**定义**：
- 假设冲突很少发生
- 事务执行时不获取锁
- 提交时检查是否有冲突

**阶段**：
1. **读阶段**：事务读取数据并执行操作
2. **验证阶段**：检查是否与其他事务冲突
3. **写阶段**：如果验证通过，写入数据

## 总结

并发控制是数据库系统的核心：
- **封锁协议**：通过锁机制控制并发访问
- **死锁处理**：预防、避免、检测和解除死锁
- **可串行化**：保证并发执行的正确性
- **实现技术**：锁管理器、时间戳、乐观并发控制

理解并发控制对于设计高性能的数据库系统至关重要。
