# 三级模式

## 概述

数据库系统的三级模式结构是数据库系统的核心体系结构，它将数据库的组织分为三个层次：外模式、模式和内模式。

### 三级模式的作用

1. **数据独立性**：物理独立性和逻辑独立性
2. **数据共享**：不同用户可以使用不同的视图
3. **数据安全**：通过外模式限制用户访问范围

## 外模式

### 定义

外模式（External Schema）是数据库用户看到的局部数据的逻辑结构和特征的描述，也称为子模式或用户模式。

### 特点

1. **局部性**：只包含用户感兴趣的数据
2. **安全性**：用户只能访问授权的数据
3. **灵活性**：不同用户可以有不同的外模式

### 示例

```sql
-- 学生视图（外模式）
CREATE VIEW student_view AS
SELECT student_id, student_name, department
FROM students
WHERE department = '计算机学院';
```

### 外模式与应用程序

每个应用程序通常对应一个外模式，应用程序只与外模式打交道，不直接访问模式和内模式。

## 模式

### 定义

模式（Schema）是数据库中全体数据的逻辑结构和特征的描述，也称为概念模式或逻辑模式。

### 特点

1. **全局性**：包含数据库的所有数据
2. **完整性**：定义数据的完整性约束
3. **一致性**：保证数据的一致性

### 示例

```sql
-- 学生表（模式）
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50) NOT NULL,
    department VARCHAR(50),
    grade INT,
    gender CHAR(1)
);
```

### 模式与外模式的关系

一个模式可以对应多个外模式，外模式是模式的子集。

## 内模式

### 定义

内模式（Internal Schema）是数据物理结构和存储方式的描述，也称为存储模式。

### 特点

1. **物理性**：描述数据的物理存储
2. **存储细节**：包括存储结构、索引、存储位置等
3. **独立性**：与硬件和操作系统相关

### 示例

```sql
-- 创建索引（内模式）
CREATE INDEX idx_student_name ON students(student_name);
```

### 内模式与模式的关系

一个模式只能对应一个内模式，内模式是模式的物理实现。

## 二级映像

### 外模式/模式映像

**定义**：定义外模式与模式之间的对应关系。

**作用**：
- **数据的逻辑独立性**：当模式改变时，只需要修改外模式/模式映像，外模式和应用程序不需要改变。

**示例**：
```
模式：students(student_id, student_name, department, grade, gender)
外模式：student_view(student_id, student_name, department)
映像：student_view ← students(student_id, student_name, department)
```

### 模式/内模式映像

**定义**：定义模式与内模式之间的对应关系。

**作用**：
- **数据的物理独立性**：当内模式改变时，只需要修改模式/内模式映像，模式和应用程序不需要改变。

**示例**：
```
模式：students表
内模式：students表的物理存储（堆文件、索引等）
映像：students表 ← 物理存储位置和结构
```

## 数据独立性

### 逻辑独立性

**定义**：用户的应用程序与数据库的逻辑结构相互独立。

**体现**：
- 当数据库的逻辑结构改变时，应用程序不需要修改。
- 例如：在students表中增加一个字段，应用程序仍然可以使用原来的外模式。

### 物理独立性

**定义**：用户的应用程序与数据库的物理存储相互独立。

**体现**：
- 当数据库的物理存储改变时，应用程序不需要修改。
- 例如：将students表从堆文件改为索引文件，应用程序仍然可以正常运行。

## 三级模式的优点

### 数据共享
- 多个用户可以共享同一个数据库
- 每个用户可以有自己的视图

### 数据安全
- 通过外模式限制用户访问范围
- 不同用户可以有不同的权限

### 数据独立
- 逻辑独立性和物理独立性
- 降低应用程序维护成本

### 数据一致性
- 统一的模式定义
- 保证数据的一致性和完整性

## 三级模式与数据库管理系统

### DBMS的作用

数据库管理系统（DBMS）负责管理和维护三级模式结构：

1. **模式定义**：DDL（数据定义语言）
2. **数据操作**：DML（数据操作语言）
3. **数据查询**：DQL（数据查询语言）
4. **数据控制**：DCL（数据控制语言）

### DDL示例

```sql
-- 创建模式
CREATE SCHEMA university;

-- 创建表
CREATE TABLE university.students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50) NOT NULL
);

-- 创建视图（外模式）
CREATE VIEW university.student_view AS
SELECT student_id, student_name
FROM university.students;
```

### DCL示例

```sql
-- 授权
GRANT SELECT ON university.student_view TO student_user;

-- 回收权限
REVOKE SELECT ON university.student_view FROM student_user;
```

## 总结

三级模式结构是数据库系统的核心：
- **外模式**：用户看到的数据视图
- **模式**：数据库的整体逻辑结构
- **内模式**：数据的物理存储结构
- **二级映像**：保证数据的逻辑独立性和物理独立性

理解三级模式结构对于设计和维护数据库系统至关重要。
