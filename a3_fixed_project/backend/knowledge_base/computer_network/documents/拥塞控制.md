# TCP拥塞控制

## 拥塞控制概述

拥塞控制是TCP的核心功能，用于防止网络因过多数据而导致拥塞。

### 拥塞的原因

1. **带宽不足**：网络带宽无法满足所有数据流的需求
2. **路由器缓冲区溢出**：路由器缓冲区有限，过多数据会导致丢包
3. **数据传输速率过高**：发送方发送速率超过网络处理能力

### 拥塞的后果

1. **丢包**：数据包丢失
2. **延迟增加**：数据包在路由器中排队等待
3. **吞吐量下降**：实际传输速率降低

## 拥塞控制机制

### 拥塞窗口（cwnd）

拥塞窗口是发送方维护的变量，表示在没有确认的情况下可以发送的最大数据量。

### 慢启动

1. 初始阶段，cwnd = 1个MSS
2. 每收到一个ACK，cwnd翻倍
3. 快速探测网络带宽

### 拥塞避免

1. 当cwnd达到ssthresh时，进入拥塞避免阶段
2. 每经过一个RTT，cwnd增加1个MSS
3. 缓慢增加发送速率

### 快速重传

1. 当收到3个重复的ACK时，认为发生了丢包
2. 立即重传丢失的段，无需等待超时

### 快速恢复

1. 检测到丢包后，不将cwnd重置为1
2. 将cwnd设置为ssthresh + 3
3. 快速恢复发送速率

## 加法增大/乘法减小（AIMD）

### AIMD策略

- **加法增大**：拥塞避免阶段，cwnd线性增加
- **乘法减小**：检测到拥塞时，cwnd减半

### AIMD的优点

1. **稳定性**：收敛到公平的带宽分配
2. **响应性**：快速降低发送速率避免拥塞

## 拥塞控制算法

### TCP Reno

Reno是最常用的TCP实现，支持：
- 慢启动
- 拥塞避免
- 快速重传
- 快速恢复

### TCP Cubic

Cubic是Linux默认的TCP实现，在高带宽网络中表现更好。

### TCP BBR

BBR是Google开发的TCP实现，基于模型的拥塞控制。

## 总结

TCP拥塞控制通过多种机制动态调整发送速率，在提高吞吐量和避免拥塞之间取得平衡。
