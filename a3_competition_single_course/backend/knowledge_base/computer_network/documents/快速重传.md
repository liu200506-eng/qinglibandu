# TCP快速重传

## 快速重传概述

快速重传是TCP拥塞控制的一种优化机制，用于在检测到丢包时立即重传，无需等待超时。

### 快速重传原理

1. **重复ACK检测**：当接收方收到乱序的段时，发送重复的ACK
2. **3个重复ACK触发**：发送方收到3个重复的ACK后，认为对应的数据段丢失
3. **立即重传**：发送方立即重传丢失的段，无需等待定时器超时

### 快速重传过程

1. 发送方发送段1、2、3、4、5
2. 段3丢失
3. 接收方收到段4，发送ACK 3（期望收到段3）
4. 接收方收到段5，发送ACK 3
5. 发送方收到第3个ACK 3
6. 发送方立即重传段3
7. 接收方收到段3，发送ACK 6（确认所有段）

## 快速重传与超时重传的对比

| 特性 | 超时重传 | 快速重传 |
|------|---------|---------|
| 触发条件 | 定时器超时 | 3个重复ACK |
| 响应时间 | 较长（RTT量级） | 较短（即时） |
| cwnd处理 | 重置为1 | 设置为ssthresh |
| 后续阶段 | 慢启动 | 快速恢复 |

## 选择性确认（SACK）

SACK是对快速重传的增强，允许接收方确认非连续的段。

### SACK工作原理

1. 接收方在ACK中包含SACK选项
2. SACK选项列出已收到但不连续的段范围
3. 发送方根据SACK信息确定需要重传的段

### SACK示例

假设发送了段1-5，段3丢失：

1. 接收方收到段1、2、4、5
2. ACK中包含SACK: [4-5]
3. 发送方知道段3丢失，立即重传

## 快速重传的优点

1. **减少延迟**：避免了超时等待时间
2. **提高吞吐量**：更快地恢复丢失的数据
3. **更好的网络利用率**：减少了不必要的带宽浪费

## 总结

快速重传是TCP拥塞控制的重要优化，通过检测重复ACK快速响应丢包。
