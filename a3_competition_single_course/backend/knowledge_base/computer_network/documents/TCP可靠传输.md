# TCP可靠传输

## 可靠传输概述

TCP（Transmission Control Protocol）是一种面向连接的可靠传输协议，确保数据的正确传输。

### 可靠传输的实现机制

1. **确认机制**：接收方收到数据后发送确认
2. **重传机制**：发送方超时后重传未确认的数据
3. **序号机制**：为每个字节分配唯一序号
4. **流量控制**：防止发送方过快淹没接收方
5. **拥塞控制**：防止网络拥塞

## 序号与确认号

### 序号

序号用于标识数据在流中的位置，TCP为每个字节分配一个序号。

- **初始序号（ISN）**：连接建立时生成的随机序号
- **序号递增**：发送数据后，序号增加数据长度

### 确认号

确认号表示期望接收的下一个字节的序号。

- **累积确认**：确认号表示所有小于该序号的数据都已正确接收
- **选择性确认（SACK）**：可以确认非连续的段

## 重传机制

### 超时重传

发送方在发送数据后启动定时器，如果在超时时间内未收到确认，则重传数据。

**超时时间的计算**：
- RTO = max(1s, min(60s, β × SRTT))
- SRTT = α × SRTT + (1-α) × RTT

### 快速重传

当收到3个重复的ACK时，立即重传丢失的段，无需等待超时。

**工作原理**：
1. 发送方发送段1、2、3、4
2. 段2丢失
3. 接收方收到段3、4后，发送ACK 2（期望收到段2）
4. 发送方收到3个ACK 2后，立即重传段2

## 数据完整性

### 校验和

TCP在每个段中包含校验和，用于检测数据传输过程中的错误。

**计算方法**：
1. 将TCP段（包括伪头部）视为16位字的序列
2. 对所有字进行累加
3. 取反得到校验和

### 序列号检查

接收方检查序列号是否按顺序到达，检测重复或乱序的段。

## 总结

TCP通过多种机制实现可靠传输，是互联网中最重要的传输协议之一。
